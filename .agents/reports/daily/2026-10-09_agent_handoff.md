## 3. Architectural & Design Decisions
| Decision | Rationale & Trade-offs | Alternatives Considered | Impact on Codebase |
| :--- | :--- | :--- | :--- |
| **Bevy 0.19 Observer Pattern for Events** | Bevy 0.19 deprecates `app.add_event` in favor of `commands.trigger(Event)` with `app.add_observer(system)`. This eliminates event buffer management and allows the Agent Harness to dispatch game events without requiring `EventWriter` parameters in every command handler. | Retaining legacy event queues or raw resource mutation. | Clean, decoupled trigger architecture across prospecting, mining, crafting, and building. |
| **Belt Backpressure via Progress Clamping** | When an item reaches `progress = 1.0` on a conveyor, progress is clamped at 1.0 until the target entity (belt/chest/hearth) can accept it. Prevents visual overlapping and loss of items during line blockages. | Discarding items or letting items pile up indefinitely on a single belt tile. | Completely deterministic factory logistics with natural backpressure propagation. |
| **Deterministic Time Testing Harness** | In Bevy 0.19, `TimePlugin` calculates delta from actual system time, breaking deterministic tick-based unit tests. Initialized `app.init_resource::<Time>()` manually without `TimePlugin` in tests, stepping via `time.advance_by(Duration)`. | Relying on real-time sleeps in unit tests. | 100% deterministic, instant unit and system tests with zero flakiness. |
| **Headless Mode Dual-Channel Architecture** | The game supports `--agent-headless` running with `agent_test` feature, providing TCP port 6550 (line-delimited harness) alongside HTTP port 15702 (BRP JSON-RPC). | Supporting only BRP or only TCP. | Enables high-level action scripts (tick control, action commands) and low-level ECS reflection queries simultaneously. |
